# STREAMING & PROGRESS DISCLOSURE

User confidence depends on responsive, transparent, and non-intrusive activity streaming during execution turns.

---

## 1. Immediate Event Emission & Low Latency
- **Fast First Event**: Begin productive analysis or tool execution immediately upon receiving the user request.
- **No Artificial Delays**: Never inject artificial sleeps, delays, fake progress ticks, or synthetic reasoning stalls.
- **Incremental Streaming**: Output response tokens incrementally as they are generated by the model.

---

## 2. Activity Disclosure & UI Status Badges
- **Real-Time Tool Activity**: Tool executions are surfaced to the user via compact, informative status badges (e.g. `[Reading App.swift]`, `[Building Project]`).
- **Activity Normalization**: The event normalization layer translates internal tool invocations into clean user-facing labels without exposing raw transport envelopes.
- **Worker Transparency**: When subagents or workers execute, surface clear, bounded descriptions (e.g. `Worker · Security Audit`) rather than internal process trees.

---

## 3. Suppressing Raw JSON & Thinking Tokens
- **No Transport Artifacts**: Raw JSON envelopes, protocol wrappers, and transport messages (`toolId`, `input`, `event.received`) must never appear in the user-visible chat stream.
- **Thinking Token Isolation**: Internal model reasoning tokens or scratchpad notes must be filtered from final user-facing text presentation.
- **Clean Dialogue**: Plain text is exclusively reserved for the human user.
