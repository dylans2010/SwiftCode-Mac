# SPDX license-text corpus (preserved from SwiftCode Legacy)

This directory holds the SPDX license-text corpus that SwiftCode Legacy
shipped under `SwiftCode/Backend/Licenses/`, preserved byte-for-byte from
`SwiftCode-Legacy @ d51a8f0d` during the Legacy -> Mac migration (Wave 18).
Every file's sha256 was verified against the migration manifest
(`classification_legacy.csv`, disposition `PRESERVE_LICENSE_OR_ATTRIBUTION`).

## Contents

- 779 SPDX license/exception texts (`.txt`), one per unique content hash.
- `LicenseCatalog.swift` — Legacy's original loader for this corpus,
  preserved as-is (not adapted). It discovers `.txt` files from the app
  bundle at runtime; wiring these texts into a SwiftPM target as resources
  and adapting the catalog is follow-up work for the wave that ports
  `LicencesAddView` (MIGRATE_AND_ADAPT). Do not edit this file in place.

## Deduplication

40 Legacy files were byte-identical to another file in the corpus, so they
were not written as duplicates (15 content groups, e.g. `GPL-3.0-only.txt`
vs `GPL-3.0-or-later.txt` vs `deprecated_GPL-3.0.txt` share one text).
The keeper in each group is the alphabetically first Legacy filename; the
full dedup table lives in the Wave 18 report. Consequence: 40 SPDX IDs
collapse onto 15 shared texts — a future catalog port that looks templates
up by filename stem will see only the keeper ID for each group unless the
deduped names are restored.

## Relationship to the notices generator

These texts are license *templates* a user can add to their own project;
they are not third-party components Ycode ships or links, so they are not
entries in `packaging/generate-notices.py` (`COMPONENTS`) and do not change
`THIRD_PARTY_NOTICES.md`. Do not add them to the generator's inputs.
